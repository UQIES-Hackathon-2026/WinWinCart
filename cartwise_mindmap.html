User-experience cycle: this is the demo story your team can build and pitch end-to-end.
1

Set a Goal

“Save $600 for a holiday.”

Creates motivation before showing banking features.
2

Set Grocery Budget

$120/week and choose what happens to underspend.

CartWise stores budget rule.
3

Create Grocery Wallet

CartWise requests wallet/card creation through the BaaS provider.

BaaS handles regulated account infrastructure.
4

Build Basket

Milk, chicken, rice, eggs, vegetables, etc.

Basket becomes optimisation input.
5

Optimise Shop

CartWise compares stores, specials, travel cost and travel time.

Example: $120 → $103 recommended.
6

Pay with CartWise

User shops with their grocery card.

MCC / spending limits can enforce purpose.
7

Track Automatically

Transaction webhook updates live grocery spending.

Optional receipt adds item-level verification.
8

Calculate Underspend

$120 budget − $103 spent = $17 available.

Savings engine applies the user's rule.
9

Move Toward Goal

Allocate $17 to the user's chosen goal or keep it as grocery buffer.

Goal progress and projections update.
10

Repeat Weekly

The behaviour loop repeats every grocery cycle.

Everyday savings compound into visible financial progress.
System boundary: this is the clean technical explanation for judges and engineers.

CartWise Client

Web / Mobile UI
Goals, budgets, basket builder, optimiser results, wallet, card, spending feed, receipt upload, savings dashboard.
Client responsibilities
Display state, validate user input, invoke backend APIs, receive live updates.
⇄

CartWise Backend

Product API
Users, goals, budgets, baskets, optimisation, transactions, savings and notifications.
Business Logic
Optimisation engine, underspend logic, goal allocation rules, receipt intelligence.
Persistence
Store application state and references to external BaaS accounts/cards/transactions.
⇄

Licensed BaaS Provider

Financial Infrastructure
Accounts/wallets, ledger, card issuing, payment processing, transaction events, card controls.
Regulated Responsibilities
KYC, AML, compliance and underlying banking/payment infrastructure.
Important: CartWise orchestrates and presents these capabilities; it does not implement the regulated banking core.
Suggested hackathon split: Front-end engineer → screens/state; Back-end engineer → product API + data + optimisation; Integration engineer → BaaS sandbox/mock + webhooks; optional CV/AI engineer → receipt OCR and item matching.
